Design

{settles} is fast and open, and open means every wallet is a public record. One address shows a balance, every payment, every trade and every launch. Traders get copied, orders get front run and creators get watched.

{name} is a layer 2 chain on {settles} where privacy is the starting point. It has three parts.

  • The chain. Accounts, transactions, blocks and state. Every change of state is a signed transaction inside a block.
  • The seal. Receipts of {name} blocks written to {settles} in a hash chain that only moves forward.
  • The door. A vault on {settles} that holds deposited {asset} and pays out withdrawals.

Accounts and transactions

A {name} account is your {settles} address. There is no new wallet and no new seed phrase.

A transaction is a canonical JSON message with a type, a body, the sender and a nonce, signed with the sender's {settles} key through the wallet's message signing. Nonces are counted per account, so a transaction can never be replayed or applied twice.

Deposits, payouts and refunds enter as system transactions, so every movement of value appears in a block.

Blocks

Transactions are ordered into blocks, one a second while there is activity and one a minute when the chain is quiet. Each block header holds:

  • height and parentHash, chaining every block to the one before it
  • timestamp and txCount
  • txRoot, the Merkle root of the block's transaction hashes
  • stateRoot, the Merkle root of the full chain state after the block

The block hash is the SHA256 of the canonical header, and the block is signed by the {name} block producer key with ed25519. In the Merkle tree a leaf is SHA256(0x00 || key || 0x00 || SHA256(value)) and each pair above it is SHA256(0x01 || left || right). Any change to any account changes the state root.

Settlement on {settles}

Every ten seconds {name} writes a receipt covering its newest blocks. A receipt carries the block range, a Merkle root over the block hashes in it, the state root after the last block, the last block hash and the transaction count.

Every receipt starts exactly one block after the one before it, so receipts never skip a block. Each one extends a hash chain:

checkpoint = SHA256(prev_checkpoint || from || to || blocks_root || state_root || last_block_hash || tx_count)

On Solana each receipt is a transaction signed by the chain authority that carries every field in a Memo instruction, so it can be read straight from the transaction and matched against the same blocks in the explorer.

On {settles} each receipt is a call to the settlement contract. The contract accepts receipts only from the chain authority, enforces that each one starts one block after the last, recomputes the checkpoint itself and emits every field in an event.

The door

A deposit sends {asset} from your {settles} wallet into the door, and {name} credits the same address in a system transaction a few seconds after {settles} confirms it.

A withdrawal is a signed {name} transaction naming any {settles} address. The amount leaves your balance in the same block, and the door pays it out as {asset}. Every payout happens exactly once: the settlement transaction is signed and recorded before it is broadcast, and a retry checks that record first. If a payout can never succeed, the amount is refunded on {name}.

Privacy

{name} separates what proves the chain from what belongs to you.

Public

  • Blocks, hashes and state roots
  • Transaction hash, type and status
  • Coin prices, curves and candles
  • Receipts on {settles}

Private

  • Who sent a transaction
  • Who received it
  • Amounts and balances
  • Who created a coin

Private account data is only served to its owner, who proves ownership by signing a fresh timestamped message with their {settles} key. The block producer orders transactions, so it processes them; nothing private is published to the explorer, the API or {settles}.

Pay, trade, launch

Payments

Send {asset} or any {name} coin to any account. Sender, receiver and amount stay private.

Pay links

Lock an amount behind a link and share it. The link holds a secret; the chain holds only its hash. Whoever opens the link claims the funds into their own account. An unclaimed link can be cancelled by its maker for a full refund.

Markets

Every coin trades on its own bonding curve inside {name}, with price, market cap and volume shown in USD. The curve is a constant product over virtual reserves, so the price moves with every trade and there is always a quote.

Launchpad

Anyone can launch a coin, and the creator earns half of every trade fee. When the curve completes, a coin set for public graduation stops trading on the curve and every holder registers a claim to any {settles} address.

Private data

Balances, history, links and withdrawals are readable only by the wallet that owns them. Sign a short message with the wallet and send three headers. One signature is good for five minutes.

x-l2-pubkey: <your address>
x-l2-ts:     <time in ms>
x-l2-sig:    <signature of "{tag} auth v1\n" + address + "\n" + ts>

Then call /api/me/balances, /api/me/history, /api/me/links and /api/me/withdrawals.

Send a transaction

A transaction is a small JSON object signed with the sender's {settles} key. The wallet signs the text {tag} tx v1, a new line, and the canonical JSON of the unsigned fields: keys sorted at every level, no spaces. The transaction hash is the SHA256 of those bytes.

import bs58 from 'bs58';

function canonicalJson(v) {
  if (v === null || typeof v !== 'object') return JSON.stringify(v);
  if (Array.isArray(v)) return '[' + v.map(canonicalJson).join(',') + ']';
  const keys = Object.keys(v).filter((k) => v[k] !== undefined).sort();
  return '{' + keys.map((k) => JSON.stringify(k) + ':' + canonicalJson(v[k])).join(',') + '}';
}

async function sendTx(wallet, type, body) {
  const base = '';
  const from = wallet.publicKey.toBase58();
  const { nonce } = await (await fetch(base + '/api/nonce/' + from)).json();
  const unsigned = { chainId: '{chainId}', from, nonce, type, body };
  const msg = new TextEncoder().encode('{tag} tx v1\n' + canonicalJson(unsigned));
  const { signature } = await wallet.signMessage(msg);
  const res = await fetch(base + '/api/tx?wait=1', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ ...unsigned, sig: bs58.encode(signature) }),
  });
  return res.json();
}

await sendTx(wallet, 'pay.transfer', { to: '<address>', asset: 'SOL', amount: '100000000' });

Questions

Do I need a new wallet?

No. Your {settles} address is your {name} account, and your existing wallet signs everything.

What can someone learn from the explorer?

That a transaction of a given type happened in a given block, and whether it applied. Not who sent it, who received it, or how much.

What can someone learn from {settles}?

That an address deposited into the door, or was paid from it, and the receipts of {name} blocks. Nothing that happens between a deposit and a withdrawal reaches {settles}.

Can I withdraw to a different address than I deposited from?

Yes. A withdrawal names any {settles} address.

How do I check that the chain is honest about its history?

Take any receipt from {settles}, find the same block range in the explorer, recompute the Merkle root of the block hashes and the checkpoint hash, and compare. Every block also carries the producer's signature over its hash.

What does a creator earn?

Half of the 1% trade fee on every buy and sell of their coin, paid into their {name} balance in the same block as the trade.
